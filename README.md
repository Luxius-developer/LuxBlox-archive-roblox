# LuxBlox — архив классического Roblox

Приватный эксперимент по совместимости с Android-клиентом 2021 года.
Текущий этап: собственный минимальный backend стартовых настроек и аккаунтов.
Это не восстановленный игровой сервис: тестовый APK подготовлен, запуск игровых мест пока отсутствует.

## Что уже реализовано

- JSON стартовых настроек `AndroidApp` по адресам `/v1/settings/application` и `/v2/settings/application`.
- Подтверждение приёма телеметрии без сохранения её содержимого.
- Экспериментальные `/v2/signup`, `/v1/login`, `/v2/login`, `/v2/logout`, `/v1/users/authenticated`.
- SQLite, хеширование паролей scrypt, ограниченные по сроку сессии, CSRF-проверка и ограничение попыток входа.
- Логи маршрутов без query string, паролей, cookies и идентификаторов устройств.
- Неизвестные маршруты возвращают 404: по ним можно дополнять сервер после проверки клиента.

Регистрация и вход проверены HTTP-тестами. Совместимость с конкретным экраном Android-клиента ещё не проверена.
Минимальный JSON настроек принят за исходную гипотезу на основе статического разбора; его достаточность для полного запуска пока не установлена.

## Локальный запуск на Linux Mint

Нужен Python 3.10 или новее. Установка пакетов Python не требуется.
В папке проекта выполнить:

```bash
sh start-local.sh
```

Проверка: <http://127.0.0.1:8080/healthz>.
Сервер слушает только loopback. Пароли и сессии сохраняются в `data/luxblox.sqlite3`, эта папка исключена из Git.
Запуск существующего APK сам по себе не направляет его на этот адрес.

## Проверки

```bash
python3 -m unittest discover -s tests -v
```

Тесты запускают временный HTTP-сервер и базу, проверяют bootstrap, регистрацию,
вход, выход, истечение сессий, CSRF, лимиты, неверный JSON и отсутствие секретов в логах.
GitHub Actions настроен на Python 3.10 и 3.12; результат CI нужно смотреть отдельно от локального запуска.

## Удалённый эксперимент

Есть Dockerfile. Для SQLite нужен постоянный каталог `/data`.
Контейнер слушает порт `8080` (можно задать `PORT`); перед ним нужен HTTPS reverse proxy,
например предоставляемый хостингом. `http.server` здесь используется для прототипа и не заменяет промышленный сервер.
Флаг `--insecure-local-cookies` допустим только для loopback-отладки; на хостинге он не нужен.
На текущем этапе лимит входа считается по адресу TCP-клиента: за прокси он может быть общим для всех пользователей.

Docker-образ не собирался. Для временного теста выбран native Python на бесплатном Render:
https://luxblox-api.onrender.com — база SQLite эфемерная по решению пользователя.

## Анализ и дальнейшие шаги

- [Результаты анализа клиента и OpenPekora](docs/analysis.md).
- [Контракт и ограничения API](docs/api.md).
- [Порядок подключения и пересборки клиента](docs/client-plan.md).
- [Временный запуск только на Render и проверка пересборки](docs/temporary-render.md).
- `tools/patch_client.py` перенаправляет проверенные Java URL-генераторы на заданный
  HTTPS API и создаёт отдельный package ID тестовой сборки. Пробная пересборка
  с адресом `.invalid` прошла, затем подготовлен APK с реальным адресом Render.
  Проверка приложения на телефоне ещё не выполнена.
- `tools/inspect_client.py` читает APK или распакованную папку и печатает ABI,
  хеши DEX/библиотек и существенные строковые константы. Ничего не изменяет.

Код сервера LuxBlox написан заново. APK, игровые бинарники, конфигурации с чужими ключами,
полный телефонный лог и исходники OpenPekora сюда не перенесены.
Проект не является официальным продуктом Roblox и не связан с Roblox Corporation или владельцами Pekora/Korone.
