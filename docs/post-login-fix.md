# Загрузка после входа: 2026-10-29

Пользователь подтвердил успешную регистрацию и вход на телефоне, но следующий
экран оставался в загрузке. Логи Render подтверждают signup/login 200 и
`/users/account-info` 200, затем пять повторов 404 для двух маршрутов:

- `/universal-app-configuration/v1/behaviors/app-policy/content`
- `/universal-app-configuration/v1/behaviors/app-patch/content`

Это следующая подтверждённая незавершённая часть протокола; не доказано, что
других блокирующих запросов нет. Обработчики сверены с
`Roblox/Roblox.Website/Controllers/RobloxApi/UniversalApp.cs` OpenPekora.
В OBB клиента `UniversalAppPolicy.lua` подключает `PolicyProvider` и читает
`app-policy` из MemStorageService.

Добавлена собственная минимальная политика интерфейса в `config/app-policy.json`:
типизированный JSON с настройками навигации, маршрутами авторизации и выключенными
неподдерживаемыми магазином/уведомлениями. Это профиль тестового backend,
не копия полной сторонней конфигурации. Совместимость всех экранов ещё не доказана.

App-patch возвращает `SchemeVersion="1"`, пустой `CanaryUserIds` и
`CanaryPercentage=0`: конфигурация существует, патч не распространяется.
GET и HEAD доступны без аккаунта, неизвестные методы/пути остаются 404.
Проверки выполняются HTTP-тестами и после выкладки через публичный HTTPS.

Исправление серверное; новый APK для этих двух маршрутов не требуется.
После деплоя временная SQLite может обнулиться: тогда тестовый аккаунт нужно
создать заново. Это ограничение выбранного Render Free без внешней базы.
