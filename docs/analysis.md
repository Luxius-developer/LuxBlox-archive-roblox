Проведены анализ структуры репозиториев, чтение относящихся к старту контроллеров и
конфигурации, разбор Dalvik-инструкций `classes.dex` через Androguard и инвентаризация

Не запускались его бинарники, миграции, игровые процессы или сценарии `tests`.

## Установленная причина остановки

Клиент устанавливает BaseUrl `www.pekora.zip/`.
На старте он запрашивает:

```text
GET https://clientsettingscdn.pekora.zip/v1/settings/application?applicationName=AndroidApp
```

Лог содержит `UnknownHostException`, затем `Failed to retrieve settings!` и
`AppSettings FAILURE`. В этом запуске DNS-резолвинг не завершился успешно; HTTP-ответ
ещё не был получен. Причина недоступности DNS глобально по одному логу не определяется.
Вход в аккаунт в этом логе не подтверждён и не опровергнут.
Инициализация AppManager завершилась `Completed OK`: сообщение об отсутствующей
`libshell-lib.so` не является показанной причиной остановки, хотя требует внимания
при дальнейшем тестировании.

Дополнительные неудачные обращения: `ephemeralcounters.api.pekora.zip` и
`ecsv2.pekora.zip/mobile/pbe` (телеметрия).

## Что подтвердил разбор DEX

- Класс `Lcom/roblox/client/b;` соответствует логам `AndroidAppSettings`.
- `Lcom/roblox/client/b$a;->a([Ljava/lang/Void;)Lcom/roblox/client/http/j;`
  требует HTTP 200, непустое тело и корректный JSON. При наличии `applicationSettings`
  извлекает этот объект, передаёт его обработчику настроек и сохраняет настройки.
- При `FFlagEnableRandomRobloxChannelSelection` может повторно запросить настройки
  другого канала. В нашем тестовом профиле этот флаг явно выключен.
- Без обёртки загрузчик имеет ветку обработки JSON напрямую. Для LuxBlox выбрана
  обёртка, совпадающая с серверной реализацией.
- Генератор URL `Lcom/roblox/client/u;` содержит `v1/login`, `v2/login`,
  `v2/signup`, `device/initialize`, проверки версии и оба поколения settings API.
- После загрузки настроек стартовая машина состояний включает подготовку ресурсов,
  получение browser tracker ID, эксперименты и проверку сессии. Отдельный правильный
  settings-ответ не доказывает готовность всего приложения.

Значения исходной серверной конфигурации — строки (`"True"`, `"False"`, числа и URL
в строковом виде). Это наблюдаемое соглашение, а не доказательство, что клиент
откажется от любого другого JSON-типа. В LuxBlox это соглашение сохранено.

## Что есть в OpenPekora

- Реальный обработчик `/v1/settings/application` и `/v2/settings/application`:
  `Roblox/Roblox.Website/Controllers/RobloxApi/FeatureFlagsRoblox.cs`.
  Он проверяет applicationName и читает соответствующий JSON.
- Конфигурация `Roblox/Roblox.Libraries/Json/AndroidApp.json` содержит 3977 настроек,
  включая адреса сторонних сервисов и встроенные токены. Целиком она не переносилась.
- Основной современный backend — C#-проекты в `Roblox/`, а не только папка `api`.
  Поэтому наличие `api/package.json` само по себе не означает полный Node.js backend.
- `game-server/README.md` прямо содержит `THIS IS OUTDATED, DO NOT USE`.
  Это старый TypeScript RCC manager; он не реализует игровой движок заново.
- `Notes.md` сообщает об отсутствии `game-arbiter`.
- `game-server/tests/package.json` содержит заглушку `npm test`, которая завершает
  выполнение с ошибкой. Скрипты тестирования вокруг RCC не являются готовым автономным
  тестовым набором: наличие папки tests не доказывает работоспособность менеджера.
- В `Controllers/RobloxApi/Login.cs` cookie жёстко привязана к стороннему домену и
  `Secure=false`. Простое копирование этого контроллера в другой домен не решит вход.
- Единой понятной лицензии на все материалы в корне не обнаружено; некоторые
  подпроекты имеют собственные отметки лицензирования. Публичное размещение кода
  само по себе не подтверждает права на все включённые бинарники и ресурсы.

Поэтому backend LuxBlox написан самостоятельно по наблюдаемым маршрутам и форматам,
а не создан копированием старого сервера с его инфраструктурными зависимостями.

## Что ещё не доказано

Дополнительно просмотрена структура OBB: ZIP с 6524 элементами. Файл
`ssl/pekora.zip`, несмотря на расширение, содержит PEM bundle из 129 CA-сертификатов.
Класс `com.roblox.engine.f` извлекает его в каталог приложения `exe/ssl`.
Следовательно, системные trust anchors из Android network_security_config не
описывают все TLS-настройки нативной части. Замена хоста требует проверки этого
bundle. Это обнаружение не является доказательством certificate pinning.

- Достаточность минимального settings-профиля для нативного загрузчика.
- Полный набор запросов после стартовых настроек и работа экранов входа/регистрации.
- Возможность заменить все нужные хосты одной строкой BaseUrl.
- Работа игровых мест, RCC, matchmaking и совместимость 2017/2018/2020.
- Работа собственного APK: он ещё не пересобран и не подписан.
