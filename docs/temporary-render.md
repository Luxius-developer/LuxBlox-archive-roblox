# Временный тест только на Render

Пользователь выбрал бесплатный Render без внешней базы. SQLite будет находиться
в `/tmp/luxblox.sqlite3`. После сна, перезапуска или деплоя тестовые аккаунты могут
исчезнуть; это принято для проверки цепочки. Supabase не изменяется.

Параметры сервиса:

- Workspace: `Sans's workspace` (подтверждён пользователем).
- Repository: приватный `Luxius-developer/LuxBlox-archive-roblox`, branch `main`.
- Runtime: Python; region: Frankfurt; compute plan: `free`.
- Build: `python -m unittest discover -s tests -v`.
- Start: `python -m server.app`.
- Environment: `LUXBLOX_HOST=0.0.0.0`, `LUXBLOX_DATABASE=/tmp/luxblox.sqlite3`,
  `PYTHONUNBUFFERED=1`; `PORT` предоставляет платформа.
- Проверка после деплоя: `/healthz`, settings JSON, временный аккаунт, вход и выход.

Первая попытка создания отклонена Render: приватный репозиторий недоступен его
GitHub-интеграции. Сервис этой попыткой не создан. Требуется добавить LuxBlox
в разрешённые репозитории GitHub App Render, сохранив репозиторий приватным.

## Тестовая пересборка

Для `Korone_2021.apk` из release `2021` проверен SHA-256 `classes.dex`:
`d355e33cc4c4148314a4707343adf59dc03766d1b8f79443049595a50a1f164f`.
Он совпадает с изученной папкой исходного клиента.

Apktool 3.0.3 успешно декодировал исходный APK и выполнил пробную пересборку.
Повторное чтение скомпилированного DEX подтвердило 17 изменённых методов;
бинарный AndroidManifest подтвердил новый package ID и label. Это проверка
сборки с адресом `.invalid`, без подписи и без запуска на телефоне.
Локальные 13 тестов backend и патчера прошли.

`tools/patch_client.py` принимает
папку декодирования и HTTPS origin будущего API. Он изменяет 17 рассмотренных Java
генераторов адресов, оставляя сигнатуры методов неизменными. Приложение получает
отдельный package ID `dev.luxius.luxblox.test2021` и имя `LuxBlox Test (2021)`.
Старая установленная Korone не должна заменяться этой сборкой.

Это профиль **java-bootstrap-only**. Он не переносит все нативные и OBB-адреса,
не отключает TLS-проверку и не доказывает работу игрового движка. Неизвестные запросы
сервер продолжает показывать как 404. После появления URL Render нужно выполнить
новую сборку с настоящим URL, подписать APK собственным тестовым ключом и проверить
его на телефоне. Тестовый адрес `.invalid` используется только для проверки сборки
и не должен выдаваться пользователю как работающее приложение.
