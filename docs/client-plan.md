# Следующий этап: подключение Android-клиента

## Перед пересборкой

1. Выбрать адрес тестового backend. Для исходного клиента настройки явно запрашиваются
   по HTTPS. Хостинг должен дать доступный URL и сертификат, доверенный Android.
   Java-сетевой слой по network_security_config использует системные сертификаты.
   У нативного слоя есть отдельный CA bundle в OBB (`ssl/pekora.zip`, фактически PEM,
   129 сертификатов). Его совместимость с сертификатом нового хостинга предстоит
   проверить отдельно. Отключать TLS-проверку ради теста не требуется и не планируется.
2. Инвентаризировать DEX и обе архитектуры нативных библиотек:

   ```bash
   python3 tools/inspect_client.py /путь/к/2021
   ```

3. Зафиксировать точную версию APK. Анализировалась папка `2021` commit
   `caff6b621f47d0b624daa11925746bc34067071a`; APK пользователя может иметь отличия.
   Обе ABI присутствуют: `armeabi-v7a`, `arm64-v8a`. Поэтому эта папка не является
   исключительно 64-битным клиентом. Совместимость с конкретным Redmi без установки
   и точного APK всё равно не доказана.

## Изменение и сборка

- Найти места построения BaseUrl и URL настроек. Проверить Android resources,
  DEX/smali, нативные строки и адреса внутри OBB. Инвентаризация пока не является
  исчерпывающим анализом OBB или строк, собранных во время исполнения.
- Пересобрать DEX/ресурсы подходящими инструментами; побайтовая замена строки
  произвольной длины повреждает структуру DEX и может повредить ELF.
- Проверить, какие поддомены выводятся из базового домена: `www`, `clientsettingscdn`,
  auth/API, event stream. Один бесплатный URL не означает поддержку всех поддоменов;
  возможно, понадобится изменить конкретные генераторы URL в приложении.
- Отдельно проверить native endpoints. Замена Java BaseUrl не гарантирует замену
  всех сетевых адресов.
- Выбрать package ID тестовой сборки и создать собственный ключ подписи, хранящийся
  вне репозитория. Изменение package ID требует согласовать providers, permissions
  и другие внутренние ссылки; не делать простой глобальный replace вслепую.
- Собрать и подписать APK, проверить подпись. Новый ключ не позволит обновить
  существующее приложение с чужой подписью как обычный update.

## Критерии первого запуска

В логе клиента должен появиться успешный разбор settings JSON и `AppSettings loaded.`,
а в логе backend — запрос settings с 200. Затем собрать новые неизвестные маршруты,
добавить подтверждённые ответы и проверить отдельный тестовый аккаунт LuxBlox.
Готовность регистрации/входа подтверждается прохождением экранов на телефоне,
а не только HTTP unit/integration tests.

Сейчас APK не собран: адрес сервера, подходящая схема хостов и ключ подписи ещё не выбраны.
Для статического анализа телефон и ADB можно отключить.
