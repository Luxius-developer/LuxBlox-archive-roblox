# R7: работа со встроенным клиентом

R7 исправляет направление R6: верхнее веб-меню и рисованная галочка убраны; страница `/my/avatar` больше не выдаёт SVG за редактор персонажа. Данные аккаунтов, инвентарь и права владельца сохранены.

## Изменения APK

В `ExtraContent/models/DataModelPatch/DataModelPatch.rbxm` найдены упакованные Luau-модули, не затронутые прежними шестью патчами обычных Lua-файлов. Их строковые шаблоны продолжали строить `avatar.<домен>`, `games.<домен>` и другие поддомены. В десяти модулях изменены 80 адресных/меню-констант. Индексы строк и байты инструкций/прототипов сохранены, контрольные суммы контейнеров пересчитаны. Отчёт: android-r7-bundle-audit.json. Патчер отказывается работать с неизвестным SHA256 исходного bundle.

Нативная плитка «Создать» в меню «Ещё» переназначена на «Админ-панель» с адресом `/admin`. Это замена существующего пункта, а не дополнительный веб-ряд. Плитка «Лента» переназначена на «Запустить 3D-плейс». Иконки и компоненты остаются встроенными. Сервер проверяет owner ID 2 независимо от видимости кнопки.

Для адреса `/games/start?placeid=1001` существующий HybridWebView теперь создаёт явный Intent в `ActivityProtocolLaunch` своего APK: action VIEW и `robloxmobile://placeid=1001`. Это штатный обработчик запуска; чужие домены и другие URL не перехватываются. Успешное создание Intent не подтверждает успешное соединение с RCC.

В старой сцене AvatarEditor.rbxl также исправлены строковые конструкции поддоменов. Проверяются package, версия, подпись и все точные изменения APK. Нативные `.so` и CA остаются побайтно прежними. Сборка использует Apktool 3.0.3, тот же ключ, versionCode 973, package com.luxius.luxblox.

## API для 3D-персонажа

Добавлены `/v1/avatar-fetch`, `/v1.1/avatar-fetch`, `Asset/BodyColors.ashx` и старый `Asset/CharacterFetch.ashx`. Формат включает `resolvedAvatarType=R6`, числовые цвета в обоих ожидаемых вариантах имён, scales, assetAndAssetTypeIds, accessoryVersionIds и реальные URL ресурсов одежды. Это данные для построения персонажа движком. Они не являются подтверждённым рендером на телефоне.

Также добавлены legacy-инвентарь и catalog item details, миниатюры Asset.ashx, корректные поля нативной сортировки игр. Реальная проверка 3D-вкладки, новых подписей пунктов и game handoff на Android остаётся обязательной: эмулятор/телефон в сборочной среде отсутствует.

Самодельная галочка удалена. Штатный рендер значка ещё не добавлен: наличие `hasVerifiedBadge` в JSON само по себе не меняет старую модель User, которая этого поля не читает. В этом обновлении значок не объявляется работающим.

## Уточнение по RCC

В `Blue7366/OpenPekora` действительно есть `RCCService/RCCService2020/RCCService.exe`, а не только скрипты менеджера. Проверка Windows PE показала версию `0,450,0,411923`, архитектуру x86. Файл не запускался. Версия отличается от клиента 0.477, поэтому совместимость нельзя объявить заранее.

Тот же репозиторий содержит Docker-путь game-server с внешним `rcc-docker`, отсутствующим в Dockerfile-контексте. Эти два пути запуска нельзя смешивать. start-rcc.sh задаёт лимит 2G и одно CPU — это настройка автора, а не измеренный минимум. На хосте с 256 МБ и 25% CPU запуск не подтверждён; прежде нужны доступ к подходящей ОС/runtime, игровой порт и измерение на одной карте. Существующие файлы и задачи на предложенном сервере не изменялись.

Первичный пример контракта изучен в `Blue7366/OpenPekora/Roblox/Roblox.Website/Controllers/RobloxApi/Avatar.cs`. Наш API реализован отдельно, исходники стороннего проекта в репозиторий не скопированы.
